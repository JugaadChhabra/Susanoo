| Resuming an interrupted run (intake / approvals endpoints → worker) | Muaaz | Always call `await susanoo.graph.resume.resume_run(graph, run_id, value)` with `config=susanoo.graph.config.run_config(run_id)` (thread_id = run_id, recursion_limit 40). Never send `Command(resume=...)` directly: `{}` re-pauses and `None` crashes inside LangGraph 1.2.14. `resume_run` validates against the pending pause's `kind`: questions `{"answers": {question_id: value}}`; scenarios `{"approved_ids": [...], "rejected_ids": [...]?, "edits": {id: {"title": ...}}?}` (approved_ids required; rejected wins); test-layer gate `{"approved": true\|false}` (only an explicit true approves). Bad input raises `ValueError` before anything runs: return 422 with a plain-English message. **Open:** `resume_run` takes no per-run lock, so two concurrent resumes of one run both run; the job queue (`SKIP LOCKED`) must make sure only one worker drives a run at a time. Exceptions other than the cost cap escape `ainvoke`: the worker must set the run to `failed`. |
